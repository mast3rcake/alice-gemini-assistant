# Развёртывание помощника через ChatGPT в режиме «Работа»

## Что передать ChatGPT

Откройте этот файл вместе с исходниками проекта или ссылкой на его GitHub-репозиторий. Напишите:

> Прочитай WORK_MODE_SETUP.md и разверни этот проект для меня. Проверь доступную среду, установи зависимости, запусти проверки и локальный сервер. Затем помоги создать мой Vercel production-проект и подключить мой навык Яндекс Алисы. Не используй чужие ключи, проекты и Telegram-чаты. Ключи я введу самостоятельно. В конце дай мне адреса, результаты проверок и команды повторного запуска.

Слово «локально» означает компьютер пользователя только при наличии инструмента исполнения на этом компьютере. Обычный облачный терминал ChatGPT — отдельная среда. Нельзя сообщать об установке на компьютер, если команды выполнены в облаке.

## Инструкция агенту

1. Прочитай README.md, package.json, vercel.json и доступные AGENTS.md. Определи ОС и место исполнения. Скажи пользователю, работаешь ли на его компьютере или в облачной среде. Если доступа к компьютеру нет, подготовь проект в доступной среде и выдай команды для компьютера; не обещай удалённую установку.
2. Используй каталог, принадлежащий текущему пользователю. Не удаляй существующие файлы и не привязывай чужой Vercel-проект. Для нового каталога клонируй предоставленный репозиторий через Git либо распакуй предоставленный архив. При отсутствии URL используй приложенные исходники, не угадывай репозиторий.
3. Проверь `node --version`, `npm --version`, при клонировании `git --version`. Требуется Node.js 24.x. Если его нет, установи официальным способом для ОС при доступных правах или дай пользователю официальный установщик https://nodejs.org/. Не проси административные права до необходимости. Не меняй системные переменные HOME, PATH и CODEX_HOME для хранения проекта.
4. Выполни `npm ci`, затем `npm test`. Не заменяй lockfile без причины. При сбое изучи ошибку, исправь её и повтори подходящую проверку.
5. Создай `.env.local` из `.env.example`, если он ещё не существует. Не перезаписывай заполненный файл. Пусть пользователь введёт ключи в локальном редакторе или Vercel. Не запрашивай ключи в сообщении и не выводи содержимое файла. Убедись только в наличии обязательных переменных без печати значений. Без ключа Gemini можно продолжить проверку сервера и приветствия; реальную генерацию отметь как непроверенную.
6. Запусти `npm start` в отдельном процессе или терминале. Это http://127.0.0.1:3000. Если порт занят, выбери свободный PORT. На macOS/Linux: `PORT=3001 npm start`; на PowerShell: `$env:PORT='3001'; npm start`. Не завершай сервер до окончания проверок.
7. В другом терминале выполни `npm run smoke`. Для нестандартного порта задай BASE_URL. После введения собственного Gemini-ключа выполни `npm run smoke -- --live`: эта проверка расходует API-квоту и должна вернуть 391. При квоте, недоступной модели или задержке покажи реальный результат, не объявляй генерацию рабочей.
8. Для Vercel используй подключённые инструменты Vercel, если они доступны. Иначе установи Vercel CLI по актуальной официальной документации https://vercel.com/docs/cli, выполни `vercel login`, затем `vercel link` в папке проекта. Пользователь входит самостоятельно. Выбери его команду и новый собственный проект. Не используй проект автора, токены автора или сохранённый `.vercel` из чужого архива.
9. В настройках проекта выбери Other, Node.js 24.x, корень репозитория. Пользователь добавляет GEMINI_API_KEY и SERPER_API_KEY в Production. Telegram-переменные и звук необязательны. После установки переменных сделай `vercel --prod` либо deployment через подключённый инструмент. Для Git-интеграции пользователь импортирует свой репозиторий в Vercel; ручной деплой сам по себе автоматическую Git-интеграцию не создаёт.
10. Дождись READY, возьми настоящий production-домен из результата. Проверь GET /api и POST-приветствие на нём; BASE_URL=https://<домен> npm run smoke. На PowerShell задай `$env:BASE_URL='https://<домен>'`, затем запускай smoke. Проверь отсутствие редиректа на вход Vercel: Яндекс не проходит Deployment Protection. Включи публичный доступ к production-webhook в соответствии с настройками проекта, не отключая защиту других проектов.
11. В Яндекс Диалогах пользователь создаёт свой навык. Backend: webhook `https://<домен>/api`. Включи хранение данных для передачи session_state. Голосовая поверхность должна поддерживаться без обязательного экрана. Проверь вкладку тестирования, затем публикацию. Активационная фраза определяется настройками навыка; не придумывай её. Колонка и тестовая вкладка проверяют разные части сценария.
12. В конце сообщи: каталог и среду исполнения, команды запуска/остановки, локальный URL, production URL, webhook URL, результаты каждого реально выполненного теста, незавершённые шаги. Не утверждай, что голос или Telegram проверен по одному лишь HTTP 200.

## Ключи и дополнения

Gemini: собственный ключ из https://aistudio.google.com/apikey; доступность зависит от региона и аккаунта. Serper: https://serper.dev/. Никаких Redis и дополнительных баз данных.

Telegram: пользователь создаёт бота у BotFather, вводит токен как TELEGRAM_BOT_TOKEN, запускает своего бота кнопкой «Старт» и задаёт свой числовой TELEGRAM_CHAT_ID. Агент не выбирает получателя по догадке. Проверять реальную доставку только по явному запросу пользователя, например фразой «Отправь в телеграм тестовое сообщение». Токен в URL Telegram API нельзя печатать в логах или командах с диагностическим выводом.

Звук приветствия: загрузить запись в ресурсы собственного навыка Яндекс Диалогов, дождаться обработки, скопировать `dialogs-upload/<skillID>/<soundID>.opus` и добавить как ALICE_GREETING_AUDIO. Можно вставить целиком тег `<speaker audio="...">`. После изменения нужен новый deployment. Запись играет только при пустой команде в новой голосовой сессии; ответы Gemini озвучиваются Алисой. Текст записи должен соответствовать приветствию в lib/fast.js, при другой записи измените его.

## Диагностика

| Симптом | Проверка |
| --- | --- |
| npm сообщает неверную версию Node | Установить именно Node.js 24.x |
| EADDRINUSE | Изменить PORT, обновить BASE_URL для smoke |
| Сервер работает, но Gemini не отвечает | Проверить наличие ключа, сеть, квоту, доступность модели; не раскрывать ключ |
| Поиск не работает | Проверить SERPER_API_KEY и лимиты Serper |
| Вебхук ведёт на вход Vercel | Проверить protection production-развёртывания |
| Колонка не запускает навык | Публикация, точное активационное имя, аккаунт Яндекса, голосовая поверхность |
| Telegram молчит | Реальные логи доставки, собственный CHAT_ID, старт бота, права доступа |
| История забывается | Хранение session_state, та же сессия, неизменный ключ Gemini |
